Scope disclosure

The swap step in every run below executes against mock_swap, a program I built and deployed myself as an explicit stand-in for a real swap venue (fixed-rate, real token transfers, real failure on insufficient pool liquidity — not a simulation). It is not Orca, Jupiter, Raydium, or any production DEX. Full detail: KNOWN_LIMITATIONS.md.

Try it yourself

Requires: Node 20+, a funded Solana devnet keypair (solana airdrop works), Anchor CLI if you want to rebuild from source.

git clone https://github.com/Portaudit/trustrail-pipelines
cd trustrail-pipelines/worker
npm install
npm run create-commitment
npm run withdraw-for-swap
npm run execute-mock-swap
npm run submit-proof
npm run get-commitment -- <commitment-address>

These are the exact scripts in worker/package.json — nothing here is simplified from what's actually in the repo.

Recovery and cancel are not npm scripts. From worker/, with a separate keypair file as settler (it must not be the commitment's payer; the scripts refuse that, it is a script choice and not a program rule): SETTLER_KEYPAIR=<path> npx tsx src/recover.ts <commitment-address> or SETTLER_KEYPAIR=<path> npx tsx src/cancel.ts <commitment-address>. recover applies to a FailedSlippage commitment whose escrow was withdrawn, or to a Locked one with the escrow withdrawn and no proof stamped, once the deadline slot has passed. cancel applies to a Locked commitment whose escrow was never withdrawn, after the deadline. release is run the same way: SETTLER_KEYPAIR=<path> npx tsx src/release.ts <commitment-address>. It applies to a Passed commitment, and unlike the other two it does not refuse a settler equal to the payer, because the program allows it.

Run B used an input of 300000 and a floor of 500000. When it ran, the scripts hardcoded an input of 1,000,000. They now read INPUT_AMOUNT, MIN_OUTPUT_AMOUNT and DEADLINE_SLOTS from the environment (defaults 1,000,000, 500,000 and 5000 slots), so Run B's input can be reproduced, and Run C used INPUT_AMOUNT=250000 DEADLINE_SLOTS=900.

Optional: set RPC_URL to your own devnet RPC endpoint (the public devnet endpoint can fail under load). If unset, the scripts fall back to the public devnet.

Correction, Oct 5, 2026: earlier versions of this page described the flow as ending in release/refund, called the page's devnet runs "verified end-to-end", and said "refund on FAIL".
